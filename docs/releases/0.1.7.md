# lazymidi 0.1.7

Visualizer polish, smoother seeking and reliable browser button visibility.

- Drawn (Sketchbook) keys share paper fills, pencil contours, hatching and motion
  with falling notes. Pause and reduced motion are respected.
- Falling black-key notes use a darker shade of their selected hand/track color.
  Muted hand notes and key highlights remain faintly visible.
- Remove animated hands, the Show hands setting and its Three.js dependency.
  Existing note hand correction/filtering and hand MIDI exports remain available.
- Repair imported background loading, retaining compatibility with both storage
  directories. Reset background restores the current theme without deleting media;
  Save appearance persists it.
- Compact playback controls, with Import .sf2 immediately before the SoundFont
  dropdown. Shared dark sliders and scrollbars cover the app, sheet viewer and player, with
  visible keyboard focus and disabled states.
- Smooth playback seeking with continuous thumb precision and one canvas update
  per animation frame. Fine volume adjustment retains its compact slider.
- Hide the legacy `_transkun` suffix in song labels. MIDI and sheet downloads
  replace it with `_lazymidi`, including older conversions. Library files and
  history IDs are preserved; source MIDI content is unchanged by filename formatting.
- Temporary notifications and errors clear after ten seconds. Progress, setup
  information and field validation remain visible.
- Browser page buttons appear only while the converter service is reachable and
  return on reconnection. Hidden-by-default styling also prevents older injected
  scripts from flashing buttons while the app is closed. Replace/reload the
  unpacked extension and refresh supported pages. Discord attachments retain
  their context-menu action.

## Upgrade and artifacts

Close older app instances before upgrading. Profiles, converter data, imported
SoundFonts and compatible Python environments are preserved. Replace the old
unpacked extension with this version and reload supported pages.

Windows release files are `lazymidi_0.1.7_x64-setup.exe`,
`lazymidi_0.1.7_windows-x64-portable.zip`,
`lazymidi_0.1.7_converter-extension.zip` and `SHA256SUMS.txt`.
Extract the full portable ZIP and keep `_up_` beside `lazymidi.exe`.
`lazymidi.exe` is the executable-only download; prefer the installer or full
portable ZIP for converter resources. No Wooting SDK, Python/model runtime or
CUDA pack is bundled.

Experimental macOS 14+ installers: `lazymidi_0.1.7_aarch64.dmg` (Apple Silicon)
and `lazymidi_0.1.7_x86_64.dmg` (Intel).
Experimental Linux x64 packages: `lazymidi_0.1.7_amd64.deb` and
`lazymidi_0.1.7_amd64.AppImage`, built on Ubuntu 22.04. Mark the AppImage executable
before launching it. Linux keyboard output requires configured `uinput` access;
global shortcuts require X11. Converter runtime selection is currently supported
only on Windows x64; MIDI/analog modules remain independent of it.

## Verification and limitations

148 frontend/extension checks, 56 Rust checks, 20 private converter-service checks
and three Python environment checks pass. Six specialized Rust measurements and
one inference test remain opt-in. TypeScript/Vite builds pass. Regression checks
cover legacy settings, filename formatting, native export suggestions, black-note
colors, background compatibility/reset, filtering, notices and existing workflows.
See [testing](../testing.md) for packaged verification.

Windows builds are unsigned. Mac apps have ad-hoc signatures and are not
notarized. Native package startup checks do not qualify physical MIDI/analog
hardware, keyboard permissions, Roblox, audio or live media-site downloads.
Those checks remain outstanding on Linux/macOS. No musical mappings or optional
SDK lifecycle changes are included.
